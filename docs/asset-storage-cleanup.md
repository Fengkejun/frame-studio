# 素材占用与安全清理

在「设置 → 素材与存储」查看当前设备全部项目的素材、项目数据与回收区占用。图片包含原图及缩略图，视频和音频按实际文件大小统计。统计范围为应用素材库、回收区和 SQLite 数据；外部成片、项目包以及模型下载目录由各自目录管理。

## 清理步骤

1. 刷新占用统计，检查未引用候选列表。每次最多选择 100 个，列表最多显示 500 项。
2. 打开清理预览，核对名称、类型、数量与大小，确认后移入应用回收区。
3. 回收区仍占用磁盘，可恢复原文件和不可变版本。恢复不会覆盖原位置已经存在的文件。
4. 需要释放空间时逐项选择「永久删除…」，核对并再次确认。永久删除的文件需要其他备份才能恢复。

操作完成后请刷新相应素材工作台。已完成的生成任务记录保留；任务输出中被清理的候选不再出现在素材列表，恢复后沿用原版本。候选引用数量在任务记录中仍代表当次生成结果。

## 引用保护

跨全部项目检查首帧、角色参考、片段选择、当前工作流、历史运行、时间线、历史成片、保存设置和生成任务输入。视频候选及回收视频的源首帧、字幕版本的源音频也保留。历史任务的输出候选本身可清理，其任务输入继续受到保护。

后台仍在提交、生成、查询或导出时，移入回收区与永久删除会被阻止。暂停或结果未知的任务保留输入引用。清理提交及永久删除前，在同一个数据库锁内重新检查引用；原生选择首帧、角色参考、片段、保存时间线和字幕也会在写入引用前检查素材是否仍可用。

素材目录中的未登记文件保留供人工检查，暂未提供孤立临时文件的自动删除。缺少全部素材文件的版本元数据保留，不移入回收区。

## 中断与兼容

SQLite schema 10 增加 `asset_trash` 操作记录，保留素材元数据、原文件名和回收文件名。移动文件前先保存意图，完成后原子提交元数据移除与回收状态。多个版本逐项处理；发生错误时检查回收区中已经完成及待完成的操作。

启动后，未完成的移入操作恢复到原位置，未完成的恢复继续执行，已确认永久删除的操作继续完成。恢复失败的记录继续保留，界面标记待完成，可检查文件和重试；不会自动覆盖冲突文件。路径检查限制操作到应用自身素材与回收目录，拒绝链接及越界文件名。

回收区记录留在原设备，不随 `.framepack` 迁移。项目包包含当前可用素材；曾在本机回收的版本可先恢复再导出。

## 验证

Rust 测试覆盖 9 → 10 升级、引用保护、移入/恢复/删除、引用变化拦截、数据库重开后的半完成移动恢复，以及越界文件名。Windows 原生脚本在隔离数据目录内校验实际文件字节数、缩略图、图片/音频/视频恢复和原绑定保持；浏览器预览保持文件操作禁用。
