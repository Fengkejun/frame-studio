# 真实 SD 与三镜头验收（2026-10-15）

## 服务接入修复

通过用户提供的中转站及密钥执行真实桌面 IPC 验证。`/v1/models` 认证 HTTP 200，但目录的 20 个型号未列出 SD；后续 sd2.0-mini 提交成功，证明目录缺项不等于实际调用被拒绝。

初版 Ark 入口真实返回 HTTP 404，因此使用用户提供的等价 `/v1/videos` 入口。SD 独立协议发送 `model`、`prompt`、字符串 `seconds` 和小写 `size`；首帧使用 `content` 中的 `image_url` 对象及 `role: first_frame`，完成后取真实返回的 `metadata.url`。没有套用 Grok 首帧字段或拼接下载地址。

首次 v1 请求连接中断，应用标记结果待核实并保留记录。用户检查后台告知查无此请求后，再执行一次最小生成。后续三个已知任务均未重复提交。

## 本地合成

使用同一项目中的三个固定生成视频版本，分别裁剪到 4 秒，加入两处 0.2 秒叠化转场、逐镜头中文字幕、本地系统语音配音及测试背景音。

- 成片：`artifacts/sd-three-shot-2026-10-15T08-35-59-476Z.mp4`
- 报告：同名 JSON，包含三条独立远程任务来源、固定资产版本、时间线、FFprobe 元数据和原生播放结果。
- 实测：11.600 秒、1280×720、H.264 视频、AAC 音频，3,771,725 字节。
- 验证：完整解码无错误、桌面播放器时间推进，1/5/9 秒采样画面逐张检查，三条中文字幕均显示正常，封面生成成功。

本地合成未调用外部服务，生成 POST 为 0。1280×720 为本地导出尺寸；源片均为 864×494，不作为原生 720P 生成证据。配音和背景音为本地素材，不作为云端 TTS 或转写验收。

## 回归与范围

60 项 Rust 测试、13 项浏览器测试、类型/Lint/格式检查、Rust Clippy 和 Windows 完整原生回归通过。原生回归覆盖 SD v1 精确字段、4K 参数、adaptive 限制、缺地址后的恢复、预算、批量队列、字幕/音频、时间线、清理与备份；这些回归使用本机协议固定素材。

本轮真实覆盖仅 sd2.0-mini 的 4 秒、480P 文生与单首帧。其他三个 SD 型号、其他尺寸、首尾帧及多参考素材尚未通过真实生成验收。实际扣费仍待服务账单核对，本地预留金额不作为费用结论。macOS 运行效果仍需对应平台验证。

新增测试脚本均按显式环境变量启用。`FRAME_STUDIO_LIVE_VIDEO_PROJECT_REPORT` 可在原隔离项目中补齐镜头，最多三个；`FRAME_STUDIO_LIVE_FILM_REPORTS` 以 JSON 数组指定三个成功报告，`FRAME_STUDIO_LIVE_FILM_VOICE` 指定本地配音文件。合成阶段不需要上游密钥。
