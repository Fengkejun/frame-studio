# 成片时间线与导出

## 从镜头到 MP4

1. 为镜头确认视频片段后，打开「时间线与导出」，把需要的版本添加到时间线。
2. 用左右按钮调整顺序，填写每段视频的开始和结束时间。时间线保存所选版本 ID 和裁剪参数，旧版本不会被新生成结果自动替换。
3. 选择 9:16、16:9 或 1:1 画幅，以及 720p 或 1080p 输出。选择保留完整画面、居中裁切铺满，或完整画面加模糊背景；统一为 30 fps、H.264 视频。旧时间线默认保留完整画面并补黑边。
4. 可为每个片段填写字幕。也可导入不超过 100 KB 的 SRT 或 VTT 文件，导出时烧录进画面。
5. 可导入不超过 20 MB 的 MP3、WAV、M4A、AAC、FLAC 或 OGG 音频，或使用 [AI 配音生成](voiceover-workflow.md)。配音选定后可使用 [自动字幕识别与校对](subtitle-workflow.md)，保存字幕版本并手动应用。试听后选作配音和循环背景音乐。音乐音量可调，输出为 AAC 音轨。
6. 点击「选择位置并导出 MP4」，在系统保存对话框中选择文件。导出会记录进度与结果，成功后在同目录生成 `.cover.jpg` 封面。
7. 画布中连接「视频节点 → 成片节点」，完成导出后点击「汇集已导出成片」。节点记录导出任务、片段版本、路径、时长、画幅和分辨率，不把媒体数据写入工作流 JSON。

「导出质量」提供「体积优先」「均衡（推荐）」和「高画质」三档。设置会随时间线和导出任务保存；均衡档保持旧项目的编码参数。成功的导出记录提供「播放成片」，播放器只允许访问该任务已经完成且仍存在的 MP4 文件，不接受任意本地路径。

导出前会检查每个片段属于当前项目、仍是当前镜头的已选视频、源首帧仍匹配，并读取媒体文件的实际时长。裁剪终点超过实际时长时会提示调整。编辑时间线后，既有成片节点结果需重新导出并汇集。

选择音频后可查看 [音频波形并调整配音起点](audio-alignment-workflow.md)，自动字幕同步后移；较长配音和字幕在成片结束处截断，手动导入字幕保留原有成片时间。

多个镜头可使用 [交叉溶解、经黑场切换及音频淡入淡出](transitions-audio-fades.md)。转场缩短成片时长，字幕、波形和输出时长同步更新。

## 分镜装配与成片审片

已选视频按当前分镜顺序展示。「按分镜装配全部已选镜头」一次装配有效选择，保留已加入镜头的裁剪与字幕，新加入的镜头默认取分镜时长与素材实际时长中的较小值。手动添加仍按点击顺序加入；与分镜不同会显示提醒，可点击「恢复分镜顺序」，保留版本、裁剪与台词。

「成片审片检查」按时间线显示镜头首帧、实际尺寸、起点、台词及播放入口，提醒核对人物外观、天气、道具与动作。按实际尺寸计算画幅占用，横屏素材放进竖屏时提示明显黑边或裁切风险，并提供按首镜头方向调整画幅的操作。模糊背景只是补齐空白，不恢复缺失画面或增强生成质量。

整段配音短于成片且未选音乐时显示尾部无外加声音的提醒；片段字幕尚未与语音分句对齐时显示说明。镜头视频原声当前不参与导出混音，声音来自选定配音和音乐。这些是制作提示，不自动判断画面美感或角色一致性。

## 按镜头对齐既有配音与字幕

选定配音后，在「按镜头对齐配音与字幕」中设置每个镜头对应的源配音起止秒数。分句按视频版本绑定，镜头换序后跟随该镜头；源音频原件保留，操作不提交模型生成请求。

对于本应用生成的配音，当生成文本逐行与当前镜头台词的顺序和内容完全一致时，可点击「按台词与停顿对齐」。应用读取本地波形，合并小于 350 毫秒的停顿，保留约 80 毫秒边缘，并要求声音段数与镜头数一致。该方法是停顿建议，不是语音识别或口型同步；请试听并人工调整。文本、段数或时长不匹配时保留原设置，支持手动填写源区间。

启用分镜配音时明确切换到片段台词字幕，清除全局配音偏移与配音淡化。每句放在对应镜头的开始（转场交界使用中点），字幕只在该句源音频长度内显示。后端检查源区间、镜头绑定、重复绑定、源音频时长和镜头可容纳时长，越界在导出前拒绝。镜头裁剪或转场变化后重新校验。分镜模式下暂停整段波形偏移、转写字幕应用及字幕导入；点击「恢复整段配音」后重新使用这些功能，不因导入字幕而静默改变配音排布。

`fit` 与 `voiceCues` 随时间线、导出快照和当前版本项目包保存；旧数据缺省为 `contain` 与空分句。项目包应使用同版本应用读取。

## 本地数据和恢复

数据库 schema 6 新增时间线草稿、音频资产和导出任务。音频原件保存在应用数据目录 `assets/`；导出 MP4 和封面位于用户选择的文件夹。导出先写入同文件夹中的唯一临时文件，成功后更名，不覆盖现有文件。应用重启时运行中的本地任务标记为「已中断」，可从当前时间线重新导出。点击「停止导出」会终止当前 FFmpeg 进程并清理临时文件。

跨设备备份可使用 [项目素材包](project-bundles.md)，包含媒体原件、绑定、时间线、配音选择和已完成成片。工作流 JSON 仅保存路径与版本引用。完整任务历史仍需备份应用数据目录。

## FFmpeg 配置与打包

桌面开发运行时优先使用应用程序旁的 `ffmpeg`、`ffprobe`，其次使用系统 PATH 中的安装。`npm run desktop:build` 在 Windows 生成 NSIS `.exe` 安装包，在 macOS 生成 `.dmg` 安装包。构建脚本从 `FRAME_STUDIO_FFMPEG_DIR` 指定的目录或 PATH 查找两个可执行文件，按 Rust target triple 放入忽略版本控制的 `src-tauri/binaries/`，再通过 Tauri `externalBin` 打包。脚本同时拷贝所选 FFmpeg 发布包中的 LICENSE 与 README；自定义发布包可通过 `FRAME_STUDIO_FFMPEG_LICENSE` 和 `FRAME_STUDIO_FFMPEG_README` 指定对应文件。每个目标系统与架构需要对应的 FFmpeg/FFprobe 二进制。所选 FFmpeg 构建须支持 `libx264`、`subtitles` 滤镜和 AAC 编码；macOS 构建还会拒绝依赖包外第三方动态库的二进制。

`.github/workflows/macos-installers.yml` 在原生 Apple Silicon 与 Intel runner 上分别构建 DMG，使用固定版本且校验 SHA256 的 FFmpeg 发布包，并在上传前执行 `npm run test:macos -- <app>`，验证应用结构、隔离数据目录启动、应用内 FFmpeg/FFprobe 能力和动态库封装。两种 DMG 当前未配置 Apple Developer ID 签名或公证；面向普通用户发布前需配置签名与公证，并核对 FFmpeg 构建及其依赖许可。Windows 开发机所用 FFmpeg 也自报 GPL 授权。

## 验证范围

`npm run test:desktop` 使用隔离项目与本地固定 H.264 视频、WAV 音频执行真实 Tauri IPC 和 FFmpeg 合成。测试核查时间线持久化、字幕滤镜、配音与背景音乐混合、输出视频和音频流、画幅尺寸、时长、封面及成片节点。该测试不调用云端生成服务；实际云端生成仍需有效服务商密钥。已在 Windows/WebView2 环境验证，其他系统需要分别构建与运行验收。

2026-10-16 增加三种画面适配的真实像素检查、分句配音截取与尾部静音检查，以及音频区间越界拦截。用户现有三镜头素材还通过本应用原生界面恢复分镜顺序、按停顿生成三句区间，导出 12 秒的 1280×720 横屏版和 720×1280 模糊背景竖屏版；完整解码、各镜头配音信号、原始文件哈希、重载持久化和成片播放均核验。没有新增云端生成任务，原片保留。人物风格、天气与源视频里已经缺失的构图仍属于素材质量问题，未将其记作已修复。71 项 Rust 测试、18 项浏览器测试、Windows 完整原生回归通过；此项不替代 macOS 运行验证。

macOS 的 WKWebView 不提供 Windows WebView2 测试所用的 CDP 接口，因此 `test:macos` 聚焦原生应用包启动与 sidecar 完整性；页面交互由跨平台 Playwright 浏览器测试覆盖，真实 IPC 的完整媒体交互仍由 Windows 原生冒烟测试覆盖。

接口依据：[FFmpeg 滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)、[Tauri 外部二进制打包](https://v2.tauri.app/develop/sidecar/)。
