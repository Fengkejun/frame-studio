- 文本章节在独立演示项目中真实调用 `https://vectio.cc/v1` 的 `grok-4.7`。
- 图片与视频章节切换到另一个项目，复用此前真实生成的红纸船首帧和 SD 视频。教程会明确说明切换，未将这些媒体称为本轮生成的动漫素材。

## 维护录制

`scripts/user-tutorial-plan.mjs` 保存旁白；`scripts/tutorial-narration.ps1` 使用本机中文语音生成 WAV；`scripts/tutorial-runtime.mjs` 连接原生 WebView2 并采集实际页面画面；`scripts/record-user-tutorial.mjs` 执行各章操作、合成字幕音轨、拼接和完整解码校验。

准备阶段使用 `scripts/create-user-tutorial.mjs` 的显式 `--configure` / `--prepare` 模式，分别配置日常应用连接、导入既有真实素材并创建隔离演示项目。准备阶段需通过进程环境提供密钥，禁止写入源文件。已有准备数据时直接运行录制脚本，避免再次导入项目。

录制需要已构建的 Windows 原生应用、WebView2、FFmpeg / FFprobe 和中文系统语音。录制脚本读取 `setup.json`，以 `recording-progress.json` 保存完成章节与真实运行 ID。重启时保留已完成章节，继续查询原工作流运行，避免因补录重复调用模型。

真实生成等待明显长于旁白时，第五章保留提交与结果的正常速度，仅压缩中间等待并在画面标注。原始录像保留。若一次录制已获得完整画面、但末尾的录制检查中断，可以显式使用 `--reuse-raw=05` 对该原始片段重新剪辑，仍需已有真实运行记录。

修改字幕切分或章节样式后，使用 `--refresh-overlays` 从保留的原始录像重新合成，不重复执行界面操作。`--rerecord=章节编号` 则显式补录指定章节；录制前应核对该章节是否包含实际服务请求。

验收包括音视频流、时长、完整解码、各章画面和字幕抽检；界面显示成功不单独作为真实生成的证据。
