# 视频批量队列

在「镜头视频」为当前视频服务保存密钥，展开「批量生成视频候选」。只列出当前有效分镜中已确认首帧、且首帧尺寸满足视频要求的镜头。勾选 1–24 个镜头，核对合计预估或预留金额后提交。

## 参数和选择

每个镜头使用自己的已确认首帧版本、分镜视频提示词和分镜时长。时长取整并限制在当前模型范围：万相 2–15 秒、MiniMax 4–15 秒、Grok 1–15 秒；服务、模型、生成方式、地区、分辨率、比例、单项预算与负面提示词沿用表单。请求快照在创建队列时保存。等待期间更换首帧或更新分镜，受影响的项会在发送前校验并记录失败，不会悄悄使用新版本。

生成结果保存为不可变视频候选，仍需播放并手动选择片段。批量生成不替换原来选定的首帧、片段或时间线。

## 调度和预算

全应用同时运行一个媒体批量队列（图片或视频）。视频按顺序生成，已有本地视频任务时等待；已知失败不阻止后续镜头。单镜头提交入口仍保留最多三个并行任务的限制。

创建前检查所有镜头的合计预算，每个镜头提交时再次检查项目剩余预算。未提交项未计入已提交任务的累计预留；其他任务消耗预算可能导致后续项被阻止。万相标价预估沿用现有地区价格表，中转站使用表单填写的每项预留金额，实际扣费以服务商账单为准。

## 暂停、恢复和重跑

- 「暂停队列」阻止后续提交，已开始的当前请求继续。停止当前任务的本地查询可在任务记录中操作；远程生成可能继续。
- 有远程任务 ID 的暂停项，继续队列时查询原任务，不再次 POST。应用重启后队列暂停，用户手动继续。
- 已知失败项可以重排；重跑分配新任务 ID，保存旧 ID，继续队列后才重新提交，可能计费。
- 提交响应丢失或远程结果未知时暂停后续派发，禁止重跑和继续。核对服务商结果和用量后可手动跳过未知项；原记录和预算保留。

## 存储和兼容

复用 schema 9 的 `image_batches` 表与队列控制命令，在请求枚举中增加 `video` 类型；旧图片记录保持兼容，无需数据库迁移。视频创建使用独立的 `start_video_batch` 命令。图片、视频界面分别显示各自队列；共享暂停、恢复、重跑和跳过逻辑。

发送前先保存提交意图及预分配子任务 ID。重启时按原子任务记录恢复，缺少提交记录则标记未知，不自动重发。任务历史留在原设备，项目包迁移媒体版本与选择关系。

## 验证范围

原生验证调用真实 Rust IPC 和本机 Wan 协议服务，返回固定 MP4，检查预算、每镜头参数、顺序、暂停后原任务恢复、失败单项重跑、未知结果阻断、首帧变化校验和原选择保持。Rust 测试检查持久化恢复及视频候选引用。

这些测试不执行云端 AI 推理；真实视频质量、账户权限与实际费用需使用有效账户验收。
