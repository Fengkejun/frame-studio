# 视频模型能力与协议适配

## 当前范围

已适配模型统一登记在 `src/shared/video-models.json`。前端直接导入该文件，Rust 在编译时嵌入同一份内容；界面选项、后端参数校验和首帧尺寸均从中读取。

当前登记万相 Wan 2.7、MiniMax-H3、Grok Imagine Video 1.5 Lite。其他模型需要先核对各自接口，再登记能力或扩展协议处理。中转站 `/v1/models` 的发现结果不直接成为已适配模型。

## 能力配置

| 字段                                | 作用                                           |
| ----------------------------------- | ---------------------------------------------- |
| `id` / `name` / `aliases`           | 请求模型 ID、显示名称及旧 ID 别名              |
| `protocol`                          | 选择已实现的协议处理                           |
| `modes` / `defaultMode`             | 支持的文生/首帧模式及切换后的默认模式          |
| `duration.min` / `duration.max`     | 单个模型的时长范围                             |
| `resolutions` / `defaultResolution` | 分辨率列表及默认值                             |
| `ratios`                            | 可提交的比例；空数组表示隐藏比例选项并省略参数 |
| `frameSizes`                        | 按分辨率指定首帧编码尺寸；原始图片保留         |

切换模型后，界面显示支持的模式、时长和分辨率。不受新模型支持的分辨率回到该模型默认值，时长限制到对应范围，比例清空；模式使用新模型默认值。批量任务使用相同的能力规则。

## 协议边界

| 协议               | 当前适配能力       | 请求和查询                                                       |
| ------------------ | ------------------ | ---------------------------------------------------------------- |
| `wan`              | 首帧图生视频       | 现有万相地区接口与异步任务查询                                   |
| `relay-content-v2` | 文生视频           | `/v2/video_generation` 与 `/v2/query/video_generation/{task_id}` |
| `relay-videos-v1`  | 文生、首帧图生视频 | `/v1/videos` 与 `/v1/videos/{id}`                                |

协议处理负责字段格式、远程 ID 提取、查询响应及下载地址解析。共用执行器负责任务持久化、预算、轮询、暂停恢复、下载入库和素材版本。

`relay-videos-v1` 表示当前中转站已实测的 JSON 协议，首帧字段为字符串，具体差异见 [中转站说明](video-relay.md)。其他服务即使也标注 OpenAI Video 兼容，仍需核对字段。

能力登记不会自动实现新的协议功能。例如 `relay-content-v2` 当前只实现文字输入，给配置增加 `frame` 会被校验拒绝；先实现参考图请求处理，再开放该模式。

配置会检查重复 ID/别名、默认项、时长、帧尺寸、协议与模式组合。未知模型在发送请求之前被拒绝，不回退成另一个模型的参数。

## 新增模型的步骤

1. 获取中转站模型详情的创建、查询 curl 和参数约束，并核对成片下载方式与计费规则。
2. 若请求和响应与现有某个协议一致，增加一个能力条目；选择合适的默认参数。模型选择、模式、时长和分辨率会随配置更新。
3. 如果字段或流程不同，在协议处理层实现新协议并补充测试。人物替换需要参考人物图与输入视频，视频增强需要输入视频；两者还需要相应的素材输入界面和请求结构。
4. 运行配置校验、请求协议测试和本机桌面验证；真实服务通过后记录所测模式和尺寸。

不要直接修改已有模型对应的协议含义。保留已使用的模型 ID、别名和查询兼容性，必要时登记新的配置版本，以便旧任务继续查询。

当前中转站预算仍由用户手动预留，万相沿用已有地区价格表；模型能力配置不把页面展示的价格自动当作实际账单。

## 旧数据与验证

既有 `VideoRequest` JSON 结构保持兼容，MiniMax 的 `MiniMax-H3` 别名继续有效。模型切换时的参数整理只发生于新表单与批量任务创建；恢复已存任务不会套用前端默认值，也不会再次提交生成。

测试覆盖配置完整性、错误配置拒绝、未知模型、别名兼容、两个中转站协议的任务 ID、模型切换后的参数清理和凭据隔离。`npm run test:desktop` 使用本机协议服务验证实际 Rust IPC、首帧尺寸、素材入库和原任务恢复。

本轮是适配层与界面配置改造，没有新增外部付费生成验收。此前真实云端结果见 [2026-10-15 验证记录](video-relay-verification-2026-10-15.md)。

2026-10-15 验证：59 项 Rust 测试、13 项浏览器测试、类型/Lint/格式检查和 Rust Clippy 通过；Windows 原生完整回归通过，覆盖三种视频协议、未知模型提交前拦截、下载恢复、批量队列、时间线、素材管理和备份。批量队列界面检查曾出现一次等待超时，复测未重现；测试现保留失败时的页面、错误和任务记录，便于定位再次出现的情况。
